## Scope and platform contracts

Only `src/media.rs`, `src/host.rs`, and `src/notch_uia.rs` changed after candidate 1. The rest of the slice, accepted visual geometry, pointer nonactivation, dock/picker behavior and redraw fields remain as candidate 1. No dependency, API feature, hook, IPC, thread, timer or deadline added. No seek/progress/art/volume/visualizer or provider-framework rewrite.

The pinned windows 0.62.2 binding supplies the `ProviderOptions_ProviderOwnsSetFocus` flag and OR operator, independently verified by both reviewers. Microsoft [SetFocus](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-irawelementproviderfragment-setfocus) documents opting out of UIA's default host focus at the fragment root. Microsoft [Cancel](https://learn.microsoft.com/en-us/windows/win32/api/asyncinfo/nf-asyncinfo-iasyncinfo-cancel) does not guarantee retirement; this batch relies only on terminal completion to reopen admission. The other three author memory-only behavioral claims were checked against primary Microsoft docs by the Opus review: see that report for receipts and the remaining foreground-rights unknown. No API signature is treated as proof of actual foreground grant.

## Deferred limits and honest boundaries

- M4C1-SOL-4 / M4C-OPUS-INFO-4: semantic UIA names still rebuilt every paint, at least six allocating constructions plus property name clones. Candidate 1 understated that cost. It is bounded transient work; optimize only in a separate justified small change. No extra semantic cache or accepted-provider rewrite in this material batch.
- M4C1-SOL-5: toggle-only player support remains excluded by the narrower provisional enabled-state mapping; actual player prevalence NOT RUN. M4C-OPUS-MIN-4's cancel-and-replace policy is removed. Busy presses now explicitly do nothing until completion; native double-press behavior still needs evidence.
- M4C-OPUS-INFO-1 lost nested-loop messages, INFO-2 cross-monitor focus transfer chain, INFO-3 release-only pointer rule, missing property-change events and hover/press feedback remain documented limits. Current root/dock latent lifecycle risks are not silently fixed.
- A command whose completion never arrives keeps the one global budget occupied, across session changes. A subscription error reserves it until shutdown. This trades subsequent command availability for a deterministic tiny-footprint bound, without polling/retry machinery. User-visible capabilities remain the player's advertised ones; busy is a command-admission policy, not a new player capability.

Real players, pointer/Narrator/keyboard, disabled-state changes under focus, Escape while hovered, close/hide/topology/text-scale/device-loss transitions, command responsiveness, idle paint/wake counts and CPU/private bytes/handles all remain DEFERRED/NOT RUN.
