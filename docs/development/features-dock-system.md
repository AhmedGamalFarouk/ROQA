# D2: taskbar buttons on the dock (2026-11-12)

> K1 (2026-11-13): keyboard and UIA/screen-reader support was removed by user decision. Keyboard, Tab, focus-ring, access-key and UIA lines below are history, not current behaviour.

Branch `feat/d2-dock-system`. No native/GUI run; nothing drawn, clicked or injected on a real screen (NOT RUN).

- **Settings:** a "Dock buttons" group, one switch each, live: Start, Search, Task View (default off), Minimized apps list, Show desktop strip (the rest default on). Keys `dbstart|dbsearch|dbtask|dbmin|dbdesk`. Applies through `relayout_docks`: each dock resizes, moves and repaints; no new surface, timer or thread. Both dock styles.
- **Layout (`dock.rs`):** `[Start][Search][Task View] | picker + apps | [chevron][strip]`; 44 DIP buttons, 8 DIP separators, 12 DIP strip flush on the far edge, all DPI-scaled and summed in pixels (`width_px`, so rounding never clips a cell). Narrow work areas clip app slots as before, never the buttons. Cell order (lead buttons, slots, tail buttons) is also the hover tween and UIA child order; `Hit`/`cell`/`cell_index`/`span`/`hit_at` are pure and tested (every mask of buttons at 96/120/144/192 DPI tiles without overlap).
- **Clicks:** `dock::send_keys` is one `SendInput` on the user's click only (Win; Win+S; Win+Tab; Win+D for the strip, the shell's own toggle). No hook, no shell mutation; nothing runs during measurement unless clicked. Pinning, drag-reorder (`drop_index` shifted by the lead buttons), picker slot, dock menu and hover previews are unchanged and keyed by slot, not cell.
- **Minimized list:** the chevron opens the existing `dock_menu` popup (same non-modal window, keyboard, UIA MenuItems) above it with the minimized windows: title plus icon, at most 12 rows, title order. Deviation from the brief: no new `EnumWindows`. The catalog already holds every window with `minimized` and `current_desktop`, so the list is `dock::minimized_windows(model, desktop_only)` (pure predicate `lists_minimized`), read when the popup opens; no extra enumeration, timer or polling. Icons come from the existing cache (those apps are dock slots, so usually warm); an uncached icon shows no picture and is not refreshed while the popup is open. A click restores and activates the window (`Action::Activate`). Nothing minimized: the click does nothing. Appears in addition to the dock's own slots, which are unchanged.
- **UIA:** each button is a named Button with Invoke: "Start", "Search", "Task View", "Show minimized apps, N windows" (N from the last catalog generation), "Show desktop" (`Button::label` is the one source of the names and tooltips). Same Invoke path as a click. Bounds follow `dock::span`.
- **Keyboard:** every dock cell (buttons and slots) is keyboard-focusable and answers UIA `SetFocus`, the same path the notch uses (`notch_uia::FOCUS`): the dock takes the foreground if Windows allows it, remembers the window it came from, and draws a focus ring (`DockScene::focus`, accent stroke as the notch). While a cell has focus: Tab / Shift+Tab and Left / Right walk the cells in a ring (clipped slots are skipped; `dock::step_cell`, `reachable`), Enter / Space press (one action per press, same `activate` as a click), Escape gives the foreground back, losing the foreground just drops the focus. Left / Right follow the screen, so they swap in a mirrored dock. Focus ends when the layout changes under it. A pointer-free user without a screen reader or voice control still has no way to start it: like the notch, there is no global hotkey (none was authorized); that is a decision for the user.
- **Tooltips:** `dock_tips.rs`, a native tooltip control owned by each dock with one tool per button (text = `Button::label`). It watches the pointer itself and runs its show delay only while the pointer is over a tool, so no timer, thread or polling is added. App slots keep the DWM preview (the picker and a pinned-not-running app have no tooltip). Tool rectangles follow `dock::span` and are re-placed on every relayout; an off button's tool is empty. A failure to create the control only loses the tooltips.
- **RTL:** `Buttons::rtl` is set from the Windows display language (`dock::system_rtl`, `LOCALE_IREADINGLAYOUT`, read once at startup; not a stored setting) and mirrors the whole dock like the taskbar: `span`, `hit_at`, `drop_index`, `separators` and `slot_center_x` are the exact mirror of the left-to-right ones (tested for every mask and DPI), so drawing, hit-testing, drag-reorder, UIA bounds, previews and the popup follow. UIA child order stays logical. The placeholder glyphs are not flipped.
- **Glyphs:** placeholders in graphics art code, one function each (`glyph_start`, `glyph_search`, `glyph_task_view`, `glyph_minimized`, `glyph_desktop`); the line-icon pass replaces only those. Hover chips use the palette's `track`.
- **Tray overflow:** not attempted. Windows has no public API to enumerate or host the notification-area (hidden tray) icons.
- **Size:** the first D2 candidate was 1,157,120 B and tripped the ratchet (limit 1,145,272 B over baseline 1,122,816, which is unchanged and not raised). The cost was mostly one more `slice::sort_by` instantiation (~9 KB). The short lists now use `sort::by` (`src/sort.rs`, a stable insertion sort, same call shape): the dock groups, the minimized list, the monitors and the full-screen list; the layout functions are `#[inline(never)]` (~2.5 KB); the relayout path exists once (`relayout_docks`); the glyph functions share one brush. Candidate: 1,134,080 B. Timers and the prayer events still use `sort_by_key` (not touched).
- **Limits:** Win+Tab and Win+S behaviour is the shell's; no tray overflow (no public API).
- **Tests:** width per button, tiling/no-overlap across masks and DPIs, hit-testing (separators, clipped bar, no strip), slot centres and drops with lead buttons, the mirrored dock against the left-to-right one (all masks, 3 DPIs, every pixel), separators, the keyboard ring (wrap, skipped clipped slots), names/keys/labels, minimized filter, both dock styles' placement with every button mask, settings round trip, menu row labels, the insertion sort.
- **NOT RUN:** real drawing and the focus ring, tooltip display and delay, hit-testing, `SendInput` into the shell, the popup, Narrator or Voice Access focus and keys, RTL on an Arabic display language, multi-monitor, Settings window fit on small screens.
