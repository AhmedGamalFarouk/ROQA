# Settings: short pages, steady frame

**Design handoff.** Replace the long forms with focused destinations. Keep the heading, navigation and Close in place; move only the active page's content. The recognizable detail is two still Lamp eyes over a rail of capsule destinations. Pages feel like short lists, not dashboards. No new settings, search, previews or save workflow. This design does not choose a renderer or claim to fix scroll latency by shortening the pages alone.

## Layout and visual language

All dimensions are DIPs at nominal text size. Coordinates start at the **client** origin. Keep the existing native caption, system menu and close box; do not add caption buttons. Stills include an illustrative 32 DIP title bar, not a custom chrome requirement.

| Part | At 880 × 680 client | Rule |
|---|---|---|
| Placement | Preferred 880 × 680, centered in the invoking ROQA window's monitor work area | Clamp outer bounds to the actual work area, including native frame, with 12 DIP margin when possible. Respect DPI/work-area changes and keep the existing singleton and foreground return. Never assume primary. |
| Rail | x 0–184, full client height; eyes at x 22, y 22; wordmark x 54; first destination y 64 | 12 inline inset, height 40, gap 4, glyph 20, icon-to-label gap 10, trailing selection dot 6. Selected capsule only; no separators or multicolour tiles. |
| Heading | x 208, y 22, w 634; viewport begins y 84 | 30/36 Display 600, caption 13/18 at y 60. Pin both; grow band for enlarged text or use compact layout. |
| Local tabs | If present: x 208, y 84; h 32, gap 6; viewport begins y 128 | Text width + 28 DIP, plus 12 DIP for the selected dot. Neutral selected fill with Lamp dot. Switch to a different short page, never a scroll anchor. No empty tabs band otherwise. |
| Viewport | x 208–842; y 84 (or 128) to 628; 4 top and 12 bottom content padding | 24 DIP inline padding and 14 DIP permanently reserved for scrollbar. Panels do not shift when the bar appears. No horizontal page scroll. |
| Group | 15/22 semibold heading, 6 gap to one filled panel | 16 gap from panel to next group heading. Panel r16, 4 panel top/bottom padding and 16 inline padding; no row gridlines, boxed outlines or shadows. |
| Row | 42 minimum (one line); 52 minimum (two lines); labelling 13/18 semibold, caption 12/16 | Match trailing control edges. Grow by wrapped line height; stack the value under its label if inline layout leaves under 160 DIP for the label. At 100% use numeric inputs 80 wide, timer 128, usual pickers 216, long pickers/path fields up to 260. Preserve full edit contents and native caret panning. |
| Control shape | 32-high buttons, edits and pickers; switch 42 × 24, knob 16, inset 4 | Switch and its row label share a hit target. Neutral track off, Lamp on (existing Settings convention); knob position also shows state. Neutral utility actions; one Lamp action on each of the Timer, Pomodoro and Water pages (Start timer, Start / pause, I drank a glass). |
| Scrollbar | Gutter x 842–856; 6-wide visible track/thumb centered; min thumb 28 | 14-wide hit target. Track inset 4 top/bottom. Draw only on overflow, without fade. Thumb length = max(28, track × viewport / content) capped at track length, linearly mapped across the remaining travel; reaches both ends. |
| Footer | x 184 onward, y 628–680; status x 208, Close trailing at x 842, min 84 × 32 | Fixed, outside viewport, fill separation. Default: “Changes apply as you go.” Replace with the relevant result or warning; never show a success over a refusal. Keep unresolved warnings until correction or route change. Grow for wrapped text; stack status over Close when needed. Close is not Cancel. |

**Colour and type.** Start from Settings palettes. Classic reference: client `#000000`, rail/footer `#0E0E10`, groups `#141416`, controls `#26262A`, selection `#3A3A40`, ink `#FFFFFF`, secondary `#9A9AA3`, icons `#DCE1E8`, Lamp `#FFB454`. Light reference: body `#ECEEF2`, ink `#14161A`, secondary `#50545F`, Lamp `#9A5200`. Midnight, Frosted tint and Liquid glass retain distinct existing surface/ink treatments, composited once over an opaque base, never live blur. Preserve existing effective Windows-accent behavior and the contrast-theme override in Settings; use system colours in contrast mode. Text/captions ≥4.5:1, focus and essential visual affordances ≥3:1 against adjacent surfaces, disabled excepted. Use a sufficiently distinct knob, chevron or other affordance, not just the fill. Segoe UI Variable with the existing fallback; tabular dimensions, durations, units and scale. Glyphs on 20 DIP grid, 1.75 round strokes. Static eyes; no decorative animation.

**Compact.** Rail only at client width ≥720 and height ≥584, or later if text scaling means it would not fit. Otherwise the category picker doubles as the page title; no repeated title or second persistent scroll region. Use 16 inline margin + 14 gutter. Picker band y 0–52; picker y 8–44 with current category 18/24 semibold. Caption y 60; viewport starts y 86. Local tabs if present begin y 86 and extend the pinned band to y 124. If full tab labels do not fit, replace the strip with a 32-high subpage picker. Below 400 client height omit the caption and start viewport at y 52, or y 90 with local tabs. Below 400 client width use 12 inline margin, stack row values when needed and wrap all important text. Target 320 × 240 logical minimum where feasible, never force a minimum larger than the work area; below it shorten bands/gaps instead of fonts and keep actions reachable by scroll. Recompute after 125/150/200% DPI, text-size, work-area and display changes; keep focused content visible. Mirror leading/trailing and tab arrows under existing RTL behavior, not paths or numbers.

## Route map and implementation inventory

Top-level order below is fixed. IDs are the current Settings controls. `+0…+N` means every entry in that range, in order. Preserve values, option order, dependencies, storage keys/limits, refusal rules and bindings. Use each control once. First open: General. Default local tab: first. Remember active subpage, offset and last focused row **for this window session only**. Do not create a store setting for navigation.

Prayer is the densest fixed route (13 controls, four groups). General can also overflow with eight displays. No nested form scroller: each display row shows number, verified primary marker, resolution, scale and switch; keys by the existing device identifier, never ordinal. Preserve the last enabled surface/display safeguards and disconnected-monitor choices. After display/drive/pin/hidden/sound changes, keep selection by stable identity where it survives, not row number. If removed, clamp selection and move focus only if needed to the next usable same-group control (otherwise next usable row, or navigation); passive refresh never fires a setting/action. Keep the moved pin selected and select a neighbour after Show in dock. Use the existing empty copy for pin/hidden lists, disable unusable controls and skip them in Tab. Preserve the full available lists, including the chosen external prayer sound and its missing-file text.

## Keyboard, scrolling and focus

- **Tab order.** One stop in the rail, one in the local tabs when present, enabled controls in visual order, then Close. Shift+Tab reverses. Compact pickers take the same stops. Start focused on General without changing anything. Rail Up/Down/Home/End and local Left/Right/Home/End move focus within their group; Space/Enter selects. Selection leaves focus in that group so Tab moves to the next group/content. A click keeps focus in the group without activating any content. Revisit a route at its remembered offset; on deliberate entry to its content return to the last focused usable row, otherwise the first. Do not let a remembered row override a later explicit navigation target. No stops on headings, glyphs or disabled controls. Retain native labels and editing; no change to dock/notch UI Automation.
- **Focus vs. scroll.** On deliberate content focus (Tab, Shift+Tab or click), minimally reveal the entire row with 6 DIP cushion; if taller than the viewport prioritize the actionable control/caret. Wheel/drag never moves focus or resets the caret, even when its row scrolls out. Do not snap back until a deliberate next focus or edit input. Focus is a visibly raised control fill with an independent neutral 3 × 20 capsule inside its leading edge; fields retain native caret/selection. Selected Lamp dot and keyboard focus are different cues.
- **One page viewport.** Wheel follows the pointer over the active viewport (including closed inputs/pickers); doesn't change their values. Wheel over header, rail and footer does nothing. Accumulate high-resolution deltas; per notch respect the Windows wheel-lines setting (one line = 18 DIP, page = viewport minus 36 DIP with 18 minimum). Precision scrolling/thumb drag follow input directly. Track click pages by the same amount. Page Up/Down pages and Ctrl+Home/End jumps when the active control does not consume the key; native editing/list/navigation semantics win. Clamp to both ends; release thumb capture on cancel, focus loss or route/DPI change. No wheel glide, bounce, scroll-dependent layout, or page animation. A route switches immediately; there are never two live pages during a transition.
- **Open lists own input.** Open with click, Alt+Down, F4, Space or Enter. Up/Down, Home/End, Page Up/Down, type-ahead, wheel and drag scroll the open list only. Highlight is tentative; click/Enter confirms; Esc cancels; Tab closes without applying and moves on. Click away dismisses without activating a row underneath; wheel outside does not leak to the page. Keep the owner/anchor and return focus to the field; close safely if the anchor becomes invalid. Use the Settings work area. Below field unless above offers more room; allow width beyond the field for long values within margins. Aim for ≤8 visible whole rows, 36 DIP minimum row height; wrap exceptionally long entries without cutting names, keep the highlight visible and support the full list. Closed values may wrap to two lines before eliding. System popup behavior that already meets this contract is preferred to a new custom popup.
- **Live changes.** Switches apply on activation, choices on confirmation, edits on Enter, blur, route change or window Close (button, Esc, X, Alt+F4). Enter in an edit validates the field without starting a timer, preview, or destructive action. Preserve an active draft through resize, repaint and unrelated refresh; wheel never commits. Keep current clamps and storage. Reflect actual applied value and give specific feedback on refusal or validation (e.g. “Use whole minutes from −30 to 30.”); refused autostart and last-surface/display switches revert in place. Theme/accent changes take effect immediately without resetting scroll, focus or drafts. Timer length stays a local draft; actions keep their current timer-tab dependency, sound behavior and progress state.
- **Owned dialogs.** Keep Windows prayer Browse, reset confirmation, Add hook/Undo/Add all reviews and result notices. As long as open, block background input, keep the source route/offset and restore focus to the triggering row (or resulting/next usable action). Esc cancels the innermost popup/dialog before it can close Settings. Keep safe default Cancel/No for file writes and reset, review of affected paths/operation, backup/recheck behavior and Codex trust/result notices. Agent rows show detected, hook added, or not installed; keep Add hook/Undo and disable Add all when nothing can be added. If a long title/path/list won't fit, scroll the details in the owned dialog and keep buttons visible, never omit affected files. Sound picker cancel/invalid network paths don't change the sound; reset changes settings only, not navigation or unrelated store items.

## Implementation and proof

- **Scroll contract.** Offset, visible rows, hit testing, focus and thumb use the same geometry. Clip the viewport; reuse layout/text measurements until its geometry or relevant data changes. Scroll updates offset, visible hit rectangles and dirty viewport/gutter, never reloads lists, discovers devices/hooks, syncs settings, erases the whole window or does I/O. No new dependency, idle timer or worker to make scroll feel fast. Shorter pages are a navigation improvement, not a substitute for measuring scroll.
- **Coverage.** Cross-check every old ID, runtime list and keyboard-only action. Exercise all five themes, DPI 100/125/150/200%, 320 × 240 logical where feasible, text scaling, RTL and contrast theme. Cover first/last scroll positions, partial rows, draft on theme/display refresh, eight monitors, empty and long pin/hidden/sound lists, key conflict/status, reset/hook safe cancellation and focus return. Run a full keyboard-only pass: General → Prayer → open and cancel dropdown → Tab below fold → edit a shift → Browse and cancel → Close. Test wheel over open/closed picker, Page Up/Down, thumb capture and resize. Run `scripts/verify.ps1` for implementation and report release size/delta.
- **Live perf gate for implementer.** On the second monitor if available, use a private test store and matched before/after DPI, viewport and refresh. Test default/compact Prayer and a long dropdown with at least 30 wheel events and three continuous drags. Record input-to-presented-movement p50/p95, missed updates, CPU, and idle wakeups after settling. Target p95 ≤2 refresh intervals, no blank frames/multi-frame backlog/lost final offset and no sustained Settings idle wakeups. If measurements are unavailable, report the remaining risk rather than declaring the lag fixed.
