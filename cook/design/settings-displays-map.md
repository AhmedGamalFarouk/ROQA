# General > Displays: a map of your screens

This refines only Displays in the [Settings design](settings-redesign.md). Keep the rest of General, the Settings frame and all settings as they are. Borrow the reference's spatial arrangement, numerals and resolution, not its green border, notch glyph or move-one-notch behavior. This is a map of independent switches, not a display arranger or a single choice.

## What it looks like

- Keep **Displays**, with “Choose where ROQA appears.” immediately below it at 12/16 DIP (4 DIP after the heading box, 6 before the group). `Show ROQA` above still decides **what** appears; Displays decides **where**. No new button, drag affordance, legend or animation.
- Use one Settings group (16 DIP radius, 16 DIP inline and 12 DIP vertical padding). Each screen is one neutral fill, shaped and positioned like its actual screen, with 8 DIP radius (16 minus the 8 DIP gutter). No outline, shadow or bezel. Center the map as a whole.
- In a tile, center a stack: **number** (26/30 semibold, tabular) and inline **Primary** (12/16 secondary ink) only on the Windows primary; **resolution and scale** (12/16, e.g. `2,560 × 1,440 · 125%`); then **On / Off** (12/16 semibold) beside the existing 42 × 24 DIP switch. Gap below identity: 2 DIP; above switch line: 4 DIP; state-to-switch: 8 DIP. Defer to existing Settings typography and effective accent. “Primary” is metadata, never a selection or state.
- On gets a raised neutral face. Off gets a quieter neutral face, still distinct from the group with readable ink. Off screens can be turned on; do not paint them as disabled controls. Reuse the Settings On switch accent, already approved for switches, and neutral Off switch; never color the tile or Primary marker with accent. State text and knob position work without color. Neutral hover/press treatments do not move geometry. Use a neutral 3 × 20 DIP keyboard focus capsule 6 DIP inside the leading edge. Keep text at ≥4.5:1 (use the neutral glyph ink if secondary ink falls short) and the focus cue ≥3:1. In contrast theme use existing system colors and keep the focus cue and switches distinct even if neutral fills collapse.

## Placement and fallback

1. Use the settled connected displays and full desktop rectangles (`Monitor.rect`, not work areas). Keep the existing Settings display number, assigned before any visual sort; it is not a store key or a promise to match Windows' Identify overlay. Keep the existing primary-at-desktop-origin rule for settled bounds; if ambiguous, don't infer primary from order or from ROQA being On. A primary screen may be Off. Display DPI is not part of map geometry; show the existing scale percentage as metadata only.
2. Translate the union of the rectangles to a local origin; fit it uniformly and center it in the group's inner width and a 160 DIP max inner height. Include negative origins, offsets and actual gaps; preserve the common scale and aspect ratios before the decorative inset. Inset each projected rectangle by 4 DIP on each edge (touching displays get an 8 DIP gutter). For one display only, cap projected width at 264 DIP. Convert final rectangles to client pixels using Settings DPI.
3. Use a list for the whole group if rectangles overlap, geometry is invalid, any inset face is smaller than 128 × 96 DIP, or actual text/control measurements plus 12 DIP side and 8 DIP vertical padding don't fit every face. Allow for the focus marker in the side padding. Don't stretch, omit, clip or pan individual displays to force a map. A compact Settings frame can still use a map if it fits. For an empty snapshot with no last valid list, show “No displays found.” with no focus stop. Keep the last valid list through transient enumeration as before.
4. The fallback is the existing two-line Settings row pattern (52 DIP minimum): `Display 1` with neutral `Primary` alongside where appropriate, metadata below, and the same `On`/`Off` and switch at the trailing edge. Keep 16 DIP inline inset minimum; wrap/stack when text or width demands it rather than truncating identity or state. Both presentations use the same page scroll. Focus order for both is top then left (right first on an identical top in RTL), with existing display number as the tiebreaker. Mirror text/control chrome in RTL, never the physical map.

## Input and state

- One existing native checkbox per display, with the full display number, primary status, resolution and scale in its native name. The entire visible tile/row is its hit target; the switch is not another stop, and gaps aren't clickable. Keep Settings Tab/Shift+Tab, Space/Enter, viewport clipping, focus reveal and page scrolling. No map arrows, new shortcuts or changes to dock/notch accessibility. Paint, hit and reveal against the same placed rectangles.
- Use existing device identity for focus and `off=` updates. Reflow, theme change and hotplug preserve focus on a surviving device; if removed, move to the next usable display or normal Settings fallback without firing an action. Keep incumbent device order for the store and last-on guard, the existing display limit, disconnected choices, Settings placement and per-monitor dock/notch placement.
- Toggling applies only to that display. Multiple displays can be On. On a refused final Off, keep that display On and focused and show “Keep at least one monitor on.” in the existing footer; no Off flash, tooltip or modal. A final-Off click must not turn another display on instead: reject that action before normalizing an all-off proposal. Keep the existing recovery for hotplug or old preferences, and the existing apply/refresh path. The global Show ROQA switches do not change display choices. No new worker, timer, polling, idle work or map animation.
