# Command center: Windows workarounds

November 24, 2026 · [Design spec](design/widgets-command-center.md). **Documented** means Microsoft publishes the contract; **reported** means source or project claims, not a reproduction here. Hardware, OS build and standard-user behavior are **unproven on Ahmed's PC**. No build, launch or OS settings changes performed. Test on the second monitor where available.

| Surface | Decision |
|---|---|
| Airplane | **Ship with fallback:** Windows Settings. **Spike first** for one-click parity only if the owner approves a private API. Do not label per-radio controls “Airplane.” |
| Hotspot | **Ship with fallback:** Windows Settings. **Spike first** for direct control; standalone desktop precedent is credible but not a supported guarantee. |
| Wi-Fi | **Ship with fallback:** saved networks in range when location access is allowed; hand new networks and passwords to Windows. |
| Bluetooth | **Ship with fallback:** status and Settings; **spike first** for optional audio-only connect/disconnect. No generic mouse action. |
| Do not disturb / Focus / Night light | **Drop** direct toggles in v1. Add Settings links only if requested; timed Focus read-only is a distinct feature. |

## 1. Airplane mode

- **Documented:** [`ms-settings:network-airplanemode`](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings) opens the page; the user clicks the real switch. [Windows can remember Wi-Fi/Bluetooth choices made in airplane mode](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows), so Airplane On doesn't guarantee both radios are Off. Let Windows own restore behavior on the real switch; remove the forced-Off rule in the spec.
- **Reported native toggle:** [SleepToAirPlane](https://github.com/peter-tanner/SleepToAirPlane/blob/d9ee8ad7c5f06f0bfe940ca662ab1b6579c19cad/SleepToAirPlane/main.cpp) activates private `CLSID_RadioManagementAPI` / `IRadioManager` through `CoCreateInstance` and calls `SetSystemRadioState`; the interface has `GetSystemRadioState`. This targets the global state, unlike the radio loop. [Microsoft confirms `RmSvc.dll` coordinates the global event](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/mb-radio-state), not the private COM ABI or standard-user access. If approved, read before setting, request an explicit target once, verify getter + shell, and fall back on failure. Do not manipulate the service itself.
- **Reject registry/WNF/modem substitutes:** [HKLM `SYSTEM\CurrentControlSet\Control\RadioManagement\SystemRadioState`](https://learn.microsoft.com/en-us/answers/questions/1144501/winui3-how-to-detect-when-user-toggles-aeroplane-m) is a reported observation. A write generally needs elevation and need not issue the service/driver event. Reverse-engineered [`WNF_SRC_SYSTEM_RADIO_CHANGED` and `WNF_CELL_AIRPLANEMODE`](https://github.com/himselfv/viper/blob/master/WnfStateNames.txt) are not public setters or stable schemas. [`IMbnRadio::SetSoftwareRadioState`](https://learn.microsoft.com/en-us/windows/win32/api/mbnapi/nf-mbnapi-imbnradio-setsoftwareradiostate) and `IMbnRadioEvents::OnSetSoftwareRadioStateComplete` affect one mobile-broadband modem, not the system switch; the [HID route](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/airplane-mode-radio-management) is for drivers/hardware.
- **If asked for a separate “Wi-Fi and Bluetooth off” action:** [`Radio::GetRadiosAsync`, `RequestAccessAsync`, `SetStateAsync`, `State`, `StateChanged`](https://microsoft.github.io/windows-docs-rs/doc/windows/Devices/Radios/struct.Radio.html) work per radio, not on the Windows switch. Keep an in-memory snapshot of only the chosen instances that were On and that ROQA confirmed Off after requesting it. [`Allowed` alone is not confirmation](https://learn.microsoft.com/en-us/uwp/api/windows.devices.radios.radio.setstateasync?view=winrt-26100). Keep instance identity or use `GetDeviceSelector` / `DeviceInformation.Id` / `FromIdAsync`, not name or kind alone. Restore only those same instances still Off and not changed independently; skip removed, externally changed, denied or hardware-disabled radios. Serialize operations, consume the snapshot on restore, don't persist it or restore on launch; no snapshot means no restore.
- **Owner PC test:** Use a wired pointer/local session. Start Wi-Fi On/Bluetooth Off, then invert the starting state; toggle both ways and check Settings + Quick Settings/icon against the independent radio states. Test an in-airplane Wi-Fi exception and a Windows-side change. For private COM, use a standard-user token and log build/HRESULTs; for a radio-only action, prove the Windows switch stays distinct and previously Off or externally altered radios are not restored.

## 2. Mobile hotspot

- **Documented contract:** [`CreateFromConnectionProfile`](https://learn.microsoft.com/en-us/uwp/api/windows.networking.networkoperators.networkoperatortetheringmanager.createfromconnectionprofile) says the factory throws without `<DeviceCapability Name="wiFiControl"/>`, and identifies `GetTetheringCapabilityFromConnectionProfile` / `DisabledBySystemCapability` as the capability check. `wiFiControl` is a [device capability, not `rescap`](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/app-capability-declarations), with location-consent implications. A plain unpackaged exe cannot declare that package capability; its Win32 manifest isn't a substitute. [`TetheringOperationalState`, `StartTetheringAsync`, `StopTetheringAsync`](https://microsoft.github.io/windows-docs-rs/doc/windows/Networking/NetworkOperators/struct.NetworkOperatorTetheringManager.html) need a manager instance, so state-only isn't a documented way around the factory. Capability isn't on/off state.
- **Reported contrary precedent, not guaranteed:** [AutoSpot's Rust source](https://github.com/data-seek/AutoSpot/blob/a068ab9b21155d921987da13d3eedbdb7289481a/src/hotspot.rs) calls these APIs and [advertises a loose exe](https://github.com/data-seek/AutoSpot). This does not establish the token, identity or all-build support. Test directly, don't reproduce its polling or use a PowerShell privilege workaround. [Sparse packaging with external location](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps) can supply identity and a manifest, but requires signing/trust, registration and capability verification. That changes distribution; drop for v1.
- **Drop substitutes:** [`netsh wlan ... hostednetwork` / `WlanHostedNetwork*`](https://learn.microsoft.com/en-us/windows-hardware/drivers/partnerapps/wi-fi-direct) target deprecated SoftAP. `netsh wlan show drivers` can verify legacy support, not Windows Hotspot state. `WiFiDirectAdvertisementPublisher` + `WiFiDirectLegacySettings` is a different local AP that can conflict with Hotspot. [`IUIAutomationTogglePattern::Toggle`](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationtogglepattern) is public, but the control tree, pattern support and timing of Settings aren't a contract. Do not automate Settings, synthesize input or steal focus. Use `ms-settings:network-mobilehotspot` then one user click; a normal clickable “Open settings” action, not a dimmed or fake state tile.
- **Owner PC test:** Native throwaway probe, same bitness as ROQA, interactive standard user. Record OS build, elevation, and [`GetCurrentPackageFullName`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getcurrentpackagefullname) returning `APPMODEL_ERROR_NO_PACKAGE`. With a shareable upstream, call `NetworkInformation::GetInternetConnectionProfile`, capability, factory and state; log HRESULT/status. Start and stop once each, verify read-back and actual Settings switch, and use a spare phone to verify sharing. Try an external toggle, missing upstream and denied/unavailable cases. If only state works, a read-on-open is possible; don't promise live state without a verified event. If direct control fails, test only the Settings handoff and leave it there.

## 3. Wi-Fi

- **Documented:** Enable [`Win32_NetworkManagement_WiFi`](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/NetworkManagement/WiFi/index.html). On a worker: `WlanOpenHandle`, `WlanEnumInterfaces`, `WlanRegisterNotification` with `WLAN_NOTIFICATION_SOURCE_ACM` only, `WlanGetAvailableNetworkList`. Use cached results first and `WlanScan` once on explicit entry/refresh if needed; reload on `wlan_notification_acm_scan_complete`, handle `_scan_fail`. Filter `WLAN_AVAILABLE_NETWORK_HAS_PROFILE` + nonempty `strProfileName`; sort connected first using `WLAN_AVAILABLE_NETWORK_CONNECTED`. Don't include manual hidden profiles in “in range.” Key by interface GUID + profile name, not displayed SSID. [`WlanConnect`](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanconnect) with `wlan_connection_mode_profile`, that profile name and interface. Don't mark Connected on request acceptance: handle ACM connection complete/fail/disconnect and refresh; correlate by interface/profile where available. [YASB uses this Native Wifi approach](https://github.com/amnweb/yasb/blob/37928dfeacc579948c4b4bf12e169bcbf6006ff2/src/core/widgets/services/wifi/wifi_managers.py).
- **Required fallback:** [Microsoft's location gate](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes) covers scans, the available list and `WlanQueryInterface(wlan_intf_opcode_current_connection)`. Don't prompt on startup or hover; `ERROR_ACCESS_DENIED` means offer Windows' list, not “No networks in range.” `WlanGetProfileList` alone cannot tell what's visible; `WlanConnectionProfileDetails.GetConnectedSsid` can optionally label the connection without scanning. Avoid notification `MSM`/`ALL` because MSM adds the `wiFiControl` check.
- Subscribe only while the page is open. [Unregister/close can wait for a callback](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanregisternotification): copy necessary event fields, return promptly; never close/unregister from the callback or share a teardown-held lock. `WlanFreeMemory` for lists; unregister and `WlanCloseHandle` on the worker. Drop old page-generation results; no polling or new idle thread.
- **New/changed credentials:** [`WlanSaveTemporaryProfile`](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlansavetemporaryprofile) persists a temporary profile from a connection/discovery; no credential UI. [`WlanUIEditProfile`](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlanuieditprofile) edits an existing named profile, not a new-network picker. Use Windows for passwords, hidden SSIDs and enterprise prompts. `ms-availablenetworks:` is an Explorer handoff [used by ExplorerPatcher](https://github.com/valinet/ExplorerPatcher/blob/master/ExplorerPatcher/dllmain.c), not guaranteed to open the wanted flyout on Windows 11. Verify it or use documented `ms-settings:network-wifi`. Windows owns that UI; don't move its window or wait indefinitely for it.
- **Owner PC test:** Two saved APs in range, an out-of-range saved AP and an unsaved secured AP. Verify correct profile, connected-first ordering and Windows agreement; change a saved password and use native UI to recover. Check location allowed and denied, external connect/disconnect, close/reopen during scan, and no idle subscription or UI waits. Test the flyout link with a secondary dock and hidden taskbar.

## 4. Bluetooth

- **Ship list/status:** [`BluetoothDevice` / `BluetoothLEDevice::GetDeviceSelectorFromPairingState(true)`](https://microsoft.github.io/windows-docs-rs/doc/windows/Devices/Bluetooth/index.html), `DeviceInformation::CreateWatcher` for the selector/appropriate kind, `System.Devices.Aep.IsConnected` for association endpoints. Deduplicate by physical container. Reuse Windows-reported batteries; [the existing battery watcher](../src/device_battery.rs#L225) includes devices/containers, not just paired Bluetooth, so don't surface USB receivers or hide dormant paired devices. `ms-settings:connecteddevices` or `ms-settings:bluetooth` (verify target) for management.
- **Audio-only spike:** Microsoft documents [`KSPROPSETID_BtAudio`](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/kspropsetid-btaudio), [`KSPROPERTY_ONESHOT_RECONNECT`](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/ksproperty-oneshot-reconnect) and [`KSPROPERTY_ONESHOT_DISCONNECT`](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/ksproperty-oneshot-disconnect); desktop examples: [YASB](https://github.com/amnweb/yasb/blob/37928dfeacc579948c4b4bf12e169bcbf6006ff2/src/core/widgets/services/bluetooth/bluetooth_audio.py) and [Bluetooth Audio Switch](https://github.com/chrispoulter/bluetooth-audio-switch). Match the paired audio device's Core Audio endpoint/KS target by physical identity (including unplugged endpoints), use `IMMDevice::Activate` for `IKsControl`, then `KsProperty` with `KSPROPERTY_TYPE_GET`; confirm via device/endpoint events. [`Win32_Media_KernelStreaming`](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/Media/KernelStreaming/index.html) provides KS bindings. Driver/endpoint access under a standard token and LE Audio coverage require a test; this is not a generic link disconnect. Never change default audio routing as a hidden side effect.
- **Drop generic hacks:** [`BluetoothSetServiceState`](https://learn.microsoft.com/en-us/windows/win32/api/bluetoothapis/nf-bluetoothapis-bluetoothsetservicestate) (`Bthprops.lib`) enables/disables services and installs/removes the mapped driver, not a reliable link toggle. No basis for safe standard-user HID controls. `BluetoothDevice` / `BluetoothLEDevice` expose status/events, not arbitrary OS-managed profile control. [`BluetoothLEDevice::FromIdAsync`](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothledevice.fromidasync?view=winrt-26100) alone doesn't connect; `GattSession.MaintainConnection` or uncached GATT discovery/I/O establishes an app BLE session, not an OS-wide mouse or headset switch. Win32 `BluetoothGATT*` is for GATT services too. [`AudioPlaybackConnection`](https://learn.microsoft.com/en-us/uwp/api/windows.media.audio.audioplaybackconnection?view=winrt-26100) streams **into the PC**, not to headphones. [`pnputil /disable-device` / `/enable-device`](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax), DevCon and device-node changes are administrative and could strand the user's input. Don't unpair to disconnect.
- **Owner PC test:** Classic headset, Bluetooth mouse and USB receiver; verify one row per paired device, updates from Windows and power cycles, honest missing battery, and correct Settings page. For the KS spike, disconnect and reconnect without unpairing or elevating, play audio, verify Windows/endpoint state and no collateral mouse or default-routing change. Repeat with LE Audio if available; otherwise record unverified. Unsupported or denied audio targets fall back to Settings.

## 5. Do not disturb, Focus, Night light and the audio picker

- **Do not disturb:** [`ms-settings:notifications`](https://support.microsoft.com/en-us/windows/experience/notifications-and-do-not-disturb-in-windows) is the supported Windows 11 handoff. `ms-settings:quiethours` and `ms-settings:quietmomentsscheduled` are legacy Focus Assist/rule routes, not commands. [`ToastNotifier.Setting`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.notifications.toastnotifier.setting) and [`UserNotificationListener`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.notifications.management.usernotificationlistener) concern app notifications or content, not the global switch. [YASB's private `IQuietHoursSettings`](https://github.com/amnweb/yasb/blob/37928dfeacc579948c4b4bf12e169bcbf6006ff2/src/core/widgets/services/dnd/dnd_api.py) uses `get_UserSelectedProfile` / `put_UserSelectedProfile` and subscribes via `RtlSubscribeWnfStateChangeNotification` to `WNF_SHEL_QUIETHOURS_ACTIVE_PROFILE_CHANGED`. A real desktop precedent, but a private ABI and selected profile can differ from effective state under rules. Don't write WNF or Quiet Hours CloudStore blobs.
- **Timed Focus:** [`Windows.UI.Shell.FocusSessionManager`](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/applifecycle/focus-session) documents `IsSupported`, `GetDefault`, `IsFocusActive`, `IsFocusActiveChanged`; `TryStartFocusSession` and `DeactivateFocus` are Limited Access Features. [Focus can enable Do not disturb](https://support.microsoft.com/en-us/windows/experience/focus-stay-on-task-without-distractions-in-windows), but DND alone is not a session. Use Settings > System > Focus if needed; verify any legacy deep link before shipping it.
- **Night light:** `ms-settings:nightlight` is the [documented handoff](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings). [PowerToys observes registry changes](https://github.com/microsoft/PowerToys/blob/main/src/modules/LightSwitch/LightSwitchService/NightLightRegistryObserver.h); [win-nightlight-cli writes reverse-engineered CloudStore blobs](https://github.com/kvnxiao/win-nightlight-cli/blob/main/docs/nightlight-registry-format.md) for the per-user `bluelightreductionstate` and `bluelightreduction.settings` records. Precedent, not a stable write API: schema, timestamps, Settings read-back and schedule/sync are at risk. No verified public Night light WNF setter; no gamma-ramp imitation.
- **Owner PC test:** Open Notifications/Night light from the links, toggle each natively and verify notification/display behavior and existing rules/schedules. If adding a Focus indicator, start/end a timed session and confirm the event; toggle DND separately and confirm it doesn't misreport Focus. If private DND is ever approved, also compare selected/effective state during an automatic rule and restore prior settings.
- **Output is already covered; input isn't.** [`policy_config::set_default`](../src/policy_config.rs#L40) calls private `IPolicyConfig::SetDefaultEndpoint` for console, multimedia and communications. [`host/levels.rs`](../src/host/levels.rs#L326) uses it for output with `ms-settings:sound` fallback; [`audio.rs`](../src/audio.rs#L705) enumerates `eRender` only. Mic picker needs `IMMDeviceEnumerator::EnumAudioEndpoints(eCapture, DEVICE_STATE_ACTIVE)`, `GetDefaultAudioEndpoint(eCapture, role)` and capture-aware events. Reuse the ID-based setter only after proving the capture roles change without render roles moving. Verify in Sound settings and a recording app, then restore; keep mic selection out of v1.

## Change the spec's order

1. Correct the design: Airplane/Hotspot are honest, enabled Settings actions by default. Remove “all radios off equals Airplane” and the forced-Off/chevron rule. Timebox Hotspot separately if the owner wants a direct toggle; private Airplane COM is a separate decision, not a prerequisite.
2. Ship the owned Quick replacement with existing radios, sliders and footer. Verify second-monitor ownership, hover/click and intentional Windows handoffs before adding pages.
3. Ship saved Wi-Fi with the location-denied and native-UI path in the same slice, then read-only Bluetooth with optional KS spike off the critical path. Leave DND/Night light and mic selection out.
4. Ship dock widgets and Settings/store together: Calendar, Prayer, Weather first; Timer and System after. Keep System open-only. Run `verify.ps1` and report byte delta for each implementation slice; this research changed no executable.
